# AI Detection Feature Documentation

## Overview

This AI detection feature uses Google's Gemini API to analyze text and determine the probability that it was generated by AI. The implementation is modular, cost-optimized, and production-ready.

## Architecture

### Service Layer (`/src/services/ai/`)

#### `geminiClient.ts`
- **Purpose**: Configures and exports the Gemini AI client with structured response schema
- **Key Features**:
  - Uses the latest Google GenAI SDK with automatic environment variable detection
  - Enforces structured JSON responses using TypeScript schema
  - Defaults to cost-efficient `gemini-3-flash` model
  - Configurable model via `GEMINI_MODEL` environment variable

#### `detectionService.ts`
- **Purpose**: Core AI detection logic with chunking and aggregation
- **Key Features**:
  - **Text Chunking**: Splits long texts into 400-word chunks for optimal API usage
  - **Concurrent Processing**: Processes all chunks in parallel for speed
  - **Result Aggregation**: Mathematically combines chunk results into final score
  - **Modular Design**: Easy to replace the underlying AI model

### API Layer (`/src/app/api/detect/route.ts`)

**Security & Rate Limiting**:
- User authentication via Supabase Auth
- Tier-based rate limiting (free: 10, pro: 1000, ultra: 10000)
- Input validation (minimum 50 words)

**Cost Optimization**:
- **Hash-based Caching**: Uses SHA-256 hashing to avoid duplicate API calls
- **Cache Storage**: Results stored in Supabase `detection_cache` table
- **Parallel Operations**: Cache lookup and usage tracking run concurrently

**Data Storage**:
- Cache: `detection_cache` table for shared results
- History: `documents` table for user-specific detection history

### Frontend Integration

#### Detection Hook (`/src/hooks/useDetection.ts`)
- Uses TanStack Query for caching and state management
- Handles API errors and loading states
- Returns structured results with cache indicator

#### Detection Page (`/src/app/detect/page.tsx`)
- **Text Input**: Large textarea for content analysis
- **Real-time Results**: Displays AI probability, confidence, and analysis
- **Sentence Highlighting**: Visually flags AI-generated sentences in red
- **Responsive Design**: Mobile-friendly layout with Tailwind CSS

## Database Schema

### Tables

#### `detection_cache`
```sql
- id: UUID (Primary Key)
- hash: VARCHAR(64) (Unique) - SHA-256 hash of input text
- result: JSONB - Structured AI detection result
- created_at: TIMESTAMPTZ
- updated_at: TIMESTAMPTZ
```

#### `documents`
```sql
- id: UUID (Primary Key)
- user_id: UUID (Foreign Key to auth.users)
- content: TEXT - Original text analyzed
- ai_score: INTEGER (0-100) - Final AI probability score
- created_at: TIMESTAMPTZ
- updated_at: TIMESTAMPTZ
```

#### `profiles` (enhanced)
```sql
- subscription_tier: TEXT ('free', 'pro', 'ultra')
- api_usage_count: INTEGER - Current usage count
- updated_at: TIMESTAMPTZ
```

### Functions

#### `increment_api_usage(user_id: UUID)`
- Atomically increments user's API usage counter
- Prevents race conditions during concurrent requests
- Used for rate limiting enforcement

## API Response Format

```json
{
  "aiProbability": 75,
  "confidence": "high",
  "flaggedSentences": [
    "This sentence appears to be AI-generated.",
    "Another flagged sentence with high probability."
  ],
  "analysis": "Aggregated analysis over 3 text chunks. Average AI probability is 75%.",
  "cached": false
}
```

## Configuration

### Environment Variables

```bash
# Required
NEXT_PUBLIC_SUPABASE_URL=your_supabase_project_url
NEXT_PUBLIC_SUPABASE_ANON_KEY=your_supabase_anon_key
GEMINI_API_KEY=your_gemini_api_key

# Optional
GEMINI_MODEL=gemini-3-flash  # Override default model
```

### Rate Limits

- **Free**: 10 detections per month
- **Pro**: 1,000 detections per month  
- **Ultra**: 10,000 detections per month

## Cost Optimization Strategies

1. **Hash-based Caching**: Identical texts return cached results
2. **Chunking**: Efficient processing of long texts
3. **Flash Model**: Uses cost-effective `gemini-3-flash` by default
4. **Parallel Processing**: Reduces overall response time
5. **Structured Responses**: Minimizes token usage with schema enforcement

## Security Considerations

1. **Authentication**: All API routes require valid Supabase session
2. **Rate Limiting**: Prevents abuse and controls costs
3. **Input Validation**: Minimum word count prevents spam
4. **Row Level Security**: Database tables protected with RLS policies
5. **API Key Security**: Gemini API key stored in environment variables
